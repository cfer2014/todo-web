# 待办清单 · Todo

一个极简单页待办应用。添加、完成、删除待办，数据只保存在浏览器本地。

整个项目只有一个 HTML 文件：CSS、JavaScript、图标全部内联，没有构建步骤、没有依赖包、没有后端、没有数据库、不需要登录。双击文件就能用。

```
todo-web/
├── 待办清单.html   # 全部代码（约 22 KB）
├── README.md
└── LICENSE         # MIT
```

## 特性

- 添加待办：输入框回车或点右侧圆形按钮
- 完成待办：点勾选框，完成后显示删除线、淡绿底色、状态标签「已完成」
- 删除待办：点行尾垃圾桶图标
- 筛选：全部 / 未完成 / 已完成，每个筛选项带实时数量
- 进度：顶部进度条与文案随完成比例变化
- 一键清除已完成
- 数据持久化：写入 `localStorage`，关闭浏览器再打开仍在
- 响应式：桌面端卡片居中，手机端贴顶铺开，360 px 宽度下无横向滚动
- 深色模式：跟随系统 `prefers-color-scheme`，无需手动切换
- 键盘可用：勾选框、删除、筛选、输入框均可 Tab 到达，焦点有可见描边

## 安装与运行

不需要安装任何东西。三种方式任选：

**方式一：直接打开**

在文件管理器里双击 `待办清单.html`，默认浏览器会打开它。地址栏是 `file:///...`，功能完整。

**方式二：拖进浏览器**

把文件拖到已打开的 Chrome / Edge / Firefox 窗口里。

**方式三：起一个本地静态服务（推荐用于开发调试）**

```bash
# 在 todo-web 目录下
python -m http.server 8000
# 然后访问 http://localhost:8000/待办清单.html
```

或者：

```bash
npx serve .
```

> 本地服务不是必需的。`file://` 下 `localStorage` 同样可用；唯一区别是不同路径会被浏览器视为不同来源，数据不互通。

## 输入条件

### 新建待办

| 条件 | 规则 |
| --- | --- |
| 输入载体 | 页面上方单行输入框，`type="text"` |
| 提交方式 | 按 `Enter`，或点输入框右侧的圆形按钮 |
| 长度上限 | 140 个字符。输入框 `maxlength="140"` 在键入时即截断，逻辑层再按 140 截一次作保底 |
| 字符类型 | 中文、英文、数字、标点、emoji 均按原样保存。长度按 UTF-16 码元计，一个 emoji 约占 2 个字符额度 |
| 首尾空白 | `trim()` 去掉前后空格，不做其他清理 |
| 连续空白 | 内部连续空白（空格、制表符、换行）压缩为单个半角空格 |
| 空输入 | 全部为空白时拒绝添加：按钮置灰不可点，回车无效果 |
| 重复内容 | 允许。不查重，两条同名待办可以同时存在 |
| 中文输入法 | 组合输入过程中按回车不会误提交（监听 `compositionstart` / `compositionend`） |
| 不支持 | 多行文本、富文本、链接、附件、截止时间、优先级、标签 |

### 其他操作输入

| 操作 | 触发 | 说明 |
| --- | --- | --- |
| 标记完成 / 取消完成 | 点击行首圆圈，或聚焦后按空格 | 复选框为原生 `input[type=checkbox]`，`Space` 可切换 |
| 删除单条 | 点击行尾垃圾桶图标 | 立即生效，无二次确认、无撤销 |
| 切换筛选 | 点击「全部 / 未完成 / 已完成」 | 不改变数据，只改变展示范围 |
| 清除已完成 | 点底栏「清除已完成」 | 仅当存在已完成项时该按钮才出现；点击后这些条目被永久删除 |

## 输出条件

列表每一行的结构固定为：勾选框 → 任务文本 → 状态标签 → 删除按钮。

| 状态 | 视觉输出 | 标签 |
| --- | --- | --- |
| 未完成 | 空心圆；文本常规颜色；无删除线 | `待办` |
| 已完成 | 圆圈填充强调色并显示对勾；文本加删除线并降为次要色；整行淡绿底 | `已完成` |

其他区域的输出：

| 输出位置 | 规则 |
| --- | --- |
| 头部主文案 | 全部未完成时显示「还有 N 件未完成」；全部完成时显示「N 件全部完成，可以收工了」；无任何条目时显示「还没有待办，先写一件」 |
| 进度条 | 宽度 = `round(已完成 / 总数 × 100)%`，总数 0 时为 0%；同时写入 `aria-valuenow` 与 `aria-valuetext` |
| 筛选计数 | 三个按钮分别显示总数、未完成数、已完成数，始终按全量数据统计，不受当前筛选影响 |
| 底栏 | 有条目时显示「共 N 件 · 已完成 M 件」；无条目时显示「数据保存在本机浏览器」 |
| 空态 | 三种文案分别对应「一条都没有」「未完成已清空」「还没有已完成项」，配同一枚线性图标 |
| 排列顺序 | 新增条目插入列表顶部；已有条目不会因为被勾选而跳位，顺序保持稳定 |
| 日期 | 头部右侧显示当天日期与星期（本地时区），仅用于展示，不参与任何业务逻辑 |

页面渲染任务文本时全部走 HTML 转义，输入内容不会被当作标签或脚本执行。

## 数据存储

- 位置：浏览器 `localStorage`
- 键名：`todo.items.v2`
- 值：JSON 数组，数组顺序即列表显示顺序

```json
[
  { "id": "m3k9x1a7", "text": "还书给图书馆", "done": true },
  { "id": "m3k9x1b2", "text": "预约周三上午的牙科复诊", "done": false }
]
```

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `id` | string | 创建时生成，用于定位列表行，不展示 |
| `text` | string | 任务名称，最长 140 字符 |
| `done` | boolean | 是否已完成 |

写入时机：添加、勾选、删除、清除已完成的每一次变更之后立即写入。

读取时机：页面加载时读取一次。键不存在则注入 3 条示例（含 1 条已完成）以便直接看到成品效果；如果本地存的是空数组 `[]`，则不会再次注入示例。

手动重置：浏览器控制台执行 `localStorage.removeItem('todo.items.v2')`，刷新后回到示例状态。

## 边界与限制

- 不做账号体系，也就没有跨设备同步。换浏览器、换电脑、清除浏览器数据，待办都会不同步或丢失。
- 不做多标签页同步。同时打开两个标签页时，后保存的一方覆盖先保存的一方。
- 存储不可用时（如禁用站点数据、部分隐私模式）页面仍可操作，但刷新即丢失，底栏会提示「当前浏览器禁止本地存储，刷新会丢失」。
- 容量受 `localStorage` 限制（一般约 5 MB），按 140 字符一条估算可存数万条，实际瓶颈通常先出现在渲染性能上。
- 不提供编辑已有文本、拖拽排序、搜索、截止日期、提醒、回收站。
- 文本列支持任意长度换行显示；宽度低于 330 px 时状态标签会隐藏，改由对勾 + 删除线表达完成状态。

## 浏览器兼容

Chrome、Edge、Firefox、Safari 的近两年版本。

依赖的现代特性：CSS 自定义属性、Flexbox、`dvh`、`:focus-visible`、`prefers-color-scheme`、`localStorage`。不支持 IE。

无网络时同样可用——没有任何外部请求，字体走系统字体栈。

## 视觉自定义

所有颜色、圆角、阴影集中在文件顶部 `:root` 里，改这一处即可换肤：

```css
:root{
  --bg:#EEEDE7;          /* 页面底色 */
  --card:#FFFFFF;        /* 卡片底色 */
  --ink:#1B1B18;         /* 主文字 */
  --ink-2:#71716A;       /* 次要文字 */
  --line:#E4E3DB;        /* 分隔线与描边 */
  --accent:#2F6B4F;      /* 强调色：勾选、进度、已完成 */
  --accent-soft:#E7EFE9; /* 已完成行底色 */
}
```

深色值在紧随其后的 `@media (prefers-color-scheme: dark)` 块中，建议两套一起改，保持对比度。

示例数据在 `<script>` 里的 `SEED` 常量，不需要示例可直接改成空数组。

## 上传到 GitHub

仓库根目录保持 `todo-web` 现在的结构，把 `README.md` 与 `待办清单.html` 一起提交即可。

```bash
cd todo-web
git init
git add .
git commit -m "feat: 极简单页待办清单"
git branch -M main
git remote add origin https://github.com/<你的用户名>/<仓库名>.git
git push -u origin main
```

也可以直接在 GitHub 网页上「Add file → Upload files」上传这两个文件。

想在线上直接访问，可在仓库 `Settings → Pages` 里选择 `Deploy from a branch`，分支选 `main`、目录选 `/ (root)`。GitHub Pages 的根路径默认找 `index.html`，如果希望 `https://<用户名>.github.io/<仓库名>/` 直接打开应用，可以额外复制一份同名文件：

```bash
cp 待办清单.html index.html          # macOS / Linux
Copy-Item 待办清单.html index.html   # Windows PowerShell
```

（中文文件名在链接里会被 URL 编码成 `%E5%BE%85%E5%8A%9E%E6%B8%85%E5%8D%95.html`，访问本身没问题，只是不好看。）
